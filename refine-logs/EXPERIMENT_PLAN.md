# TELGEN 与 Q-CAST 周期微批次实验计划

**最新修订：2026-08-12**

## 目标

在完全相同的滚动请求队列和 SeQUeNCe 物理环境中，比较 TELGEN 联合路径—构造规划器与 width-one Q-CAST 固定构造基线。主指标优先比较完成请求数，在完成数相同时再比较平均截尾延迟；规划耗时单独报告。本实验不使用泊松到达。

## 默认协议

| 项目 | 固定设置 |
|---|---|
| 拓扑 | 64 节点自然连通 Waxman 图 |
| Waxman 参数 | alpha=0.15，beta=0.45 |
| 连通方式 | 不补 MST，不人工加边；不满足端点约束则重新生成 |
| 请求端点 | 源宿最短路径距离严格为 4 跳 |
| 总请求数 | 100 |
| 周期到达 | 每 4 个时隙固定产生 10 个请求 |
| 到达时隙 | 0、4、8、……、36 |
| TTL | 每个请求自到达起 16 个时隙 |
| episode 终点 | 52，用于排空最后一批请求 |
| 路径候选 | Yen 最短简单路径，最多 4 条 |
| 构造候选 | 每条路径最多 5 棵顺序保持交换树 |
| TELGEN 教师 | 两阶段 LP；先提高期望完成质量，再降低完成延迟 |
| Q-CAST | 相同路径数，固定 left-deep 构造，不使用 TELGEN LP 或解码器 |
| 物理参数 | 生成概率 0.8，交换概率 0.9，链路内存 2，max_width=1 |
| 物理时间 | 链路距离 1000 米，时隙 50,000,000 ps |

## 每轮决策语义

控制器仅在周期边界 `t=0,4,8,...,48` 决策。每轮只看当前已经到达且未完成、未超时的请求，包括：

- 本轮新到达请求；
- 上轮未接纳的积压请求；
- 物理失败后已清理、且仍在 TTL 内的请求。

新计划只能从当前周期 `[t,t+4)` 内启动。完整构造不受下一决策点截断，可以跨周期完成，但不得超过请求截止时隙或 episode 终点。已经启动的计划不会被重排，其未来资源—时隙占用作为后续规划的硬预留。

## 公平性契约

- 每个 seed 的 TELGEN 与 Q-CAST 共享完全相同的 `EpisodeSpec`。
- 两种方法分别创建独立但配置相同的持久 SeQUeNCe 物理执行器。
- 两种方法共享到达序列、待处理队列语义、决策周期、路径上限、TTL、物理参数和评价指标。
- 规划层只提交中性的路径—构造 DTO；生成、交换、内存、保真度、失败、清理和物理时间全部由 SeQUeNCe 决定。
- Q-CAST 是统一滚动环境下的适配基线，不等同于原论文中的清空式批次协议。

## 判优规则

1. 主指标是每个 episode 完成请求数。
2. 完成数相同时，再比较平均截尾完成延迟。
3. `mean_decision_seconds` 单独报告，不与业务质量混合。
4. 正式结果使用 100 个配对 seed，并报告配对 bootstrap 置信区间和配对随机化检验。
5. 除 `slot_completion_overrun` 外的调度违例、物理后端拒绝或完成后端点/保真度检查失败，都会使相应 episode 不能用于判优。

## Sanity 门槛

正式运行前先用 6 个请求做小规模验证：每批 2 个、间隔 2、TTL=6、horizon=10。必须确认：

- 到达序列为 `0,0,2,2,4,4`；
- 决策发生在周期边界；
- 所有新计划都在当前周期内启动；
- 至少一个完整构造可以跨过下一决策点；
- 未接纳请求会进入下一轮；
- 物理失败请求在 TTL 内可以重试；
- 运行中计划的跨周期资源得到预留；
- 未来请求不可见；
- TELGEN 与 Q-CAST 使用完全相同的 EpisodeSpec；
- 无资源超卖。

## 输出

- 单 seed 版本化 JSON/CSV；
- 100 episode 汇总 JSON/CSV/Markdown；
- 完成数、完成率、截尾延迟、成功延迟、规划耗时和重试次数；
- 调度、物理可执行性和公平性审计信息。
